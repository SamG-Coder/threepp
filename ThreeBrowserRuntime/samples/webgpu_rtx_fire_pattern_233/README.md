# RTX Fire Pattern 233

`RTX Fire Pattern 233` is an original audiovisual ThreeBrowser Runtime sample.
Its three-minute score, **CIN/SIN — Pattern of Fire +233**, drives a suspended
three-dimensional instrument made from exactly 233 deterministic fire nodes.
The score and sculpture share the exact seed:

```text
p4 + 11c9h 9fwhsa assa dasd sa u923t u3240-9t 0w3
```

The seed is hashed once and used by both the score generator and the spatial
`cin`/`sin` pattern. Each of the WAV's 233 ordered RIFF cue points addresses a
corresponding node, so musical accents travel through the same authored form
that is visible on screen. A quiet passage still has shape; a crescendo grows
through space instead of merely scaling every flame at once.

## Original three-minute score

`assets/cin-sin-fire-pattern-233.wav` is an original, deterministic 48 kHz
stereo PCM16 master generated by `tools/generate-fire-score.mjs`. It lasts
exactly **3:00 (180 seconds)** and does not loop. Its nine sections introduce new
rhythm, harmony, register, orchestration and spatial cue paths rather than
repeating one short bar for the entire runtime. The checked-in WAV is the
playback master; the generator and score table are included so it can be
reproduced and tested without a network connection or downloaded music.

The visual controller reads the native audio clock and embedded cue packets.
That keeps beat-triggered flares attached to the actual output device timeline
instead of estimating song position from animation frames. When native cue
polling is unavailable, the same project-owned score table supplies a
deterministic visual fallback.

Regenerate the soundtrack from the sample directory:

```powershell
node .\tools\generate-fire-score.mjs
```

## Honest WebGPU/RTX rendering

This is a **hybrid real-time WebGPU/RTX frame**, not an offline path tracer.
Three.js WebGPU rasterizes primary visibility, translucent flame volumes,
embers, smoke, the 233-node instrument and its environment. The ThreeBrowser
ray-query bridge augments that authored raster with native visibility,
reflections, contact shadow and ambient-occlusion information from a bounded
triangle scene. The exact raster color remains the source image, and both RTX
and fallback paths finish through one tone-mapped surface presentation.

The sample owns its score, geometry, procedural materials, animation and RTX
integration in JavaScript. It does not require sample-specific C++, a custom
Runtime build, downloaded models, external textures or third-party music.

## Controls

- `M` — start or mute the music
- `P` — pause or resume the audiovisual timeline
- `Space` — launch a manual flare through the 233-node pattern
- `C` — toggle the authored automatic camera flight
- `X` — compare native RTX augmentation with the raster fallback
- `R` — restart the song, score and fire sequence from zero
- `1`–`9` — jump to the start of any score movement
- drag — orbit the camera around the fire instrument
- wheel — dolly between the complete sculpture and node-level detail

## Run

With an existing ThreeBrowser Runtime build, no native rebuild is required:

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File C:\ThreeBrowser\ThreeBrowserRuntime\run.ps1 `
  C:\ThreeBrowser\ThreeBrowserRuntime\samples\webgpu_rtx_fire_pattern_233\site-entry.mjs
```

The sample also appears automatically as **Webgpu Rtx Fire Pattern 233** in the
Runtime launcher's Demos library because its folder contains `site-entry.mjs`.
