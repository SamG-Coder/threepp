# Cloudflight Ocean

`webgpu_cloudflight_ocean` is a first-person native WebGPU/TSL flight study
for ThreeBrowser Runtime. It places the camera inside a responsive procedural
cockpit, moves through a changing marine cloud deck and retains a readable
ocean beneath breaks in the weather. The aircraft, instruments, atmosphere,
clouds, rain, ocean and visible interface are generated by JavaScript rather
than downloaded scene assets or HTML overlays.

## Rendering design

- The flight model owns aircraft attitude, airspeed, altitude and control
  response. The cockpit remains attached to that moving frame while the camera
  receives restrained vibration and weather-dependent motion cues.
- Layered procedural cloud fields provide large weather fronts, local density,
  changing visibility, sun transmission and depth-bearing parallax. Rain and
  windscreen effects share the same weather state instead of running as an
  unrelated screen effect.
- The distant ocean reuses the JavaScript/TSL wave, roughness and atmospheric
  ideas established by the Moonlit Open Ocean sample. Its live sky response is
  evaluated by the page so clouds and illumination remain coherent when the
  aircraft crosses the cloud deck.
- Instruments and help are rendered into the WebGPU canvas. `index.html`
  contains no visible UI and exists only as a portable module bootstrap.

## Generic RTX boundary

This demo does not add a flight renderer, cloud model, ocean shader or weather
system to C++. All user-visible behavior remains in `src/` as ordinary
Three.js/TSL content.

When available, the page may request NVIDIA Reflex through the existing
`navigator.gpu.threeBrowserRTX` feature bridge. Reflex is a reusable runtime
feature: the page selects a mode, reads the returned support/configured/active
status and restores the previous mode during cleanup. Requesting Reflex does
not transfer any scene or simulation policy to native code.

The bridge's ray-query scene is intentionally not used as a substitute for
this dynamic world. Its current acceleration-structure contract represents
immutable opaque world-space triangles. A cockpit attached to the aircraft is
moving geometry, the ocean deforms every frame and clouds and precipitation
are volumes rather than opaque triangles. Registering any of them as a static
scene would produce stale or misleading shadows and reflections.

The native boundary therefore remains limited to generic GPU capability
reporting, synchronization, validated resource interop and optional reusable
features such as Reflex. Cockpit layout, flight controls, cloud density and
scattering, precipitation, wind, wave spectra, Fresnel response, weather
presets, camera behavior, exposure and composition remain page-owned. A future
native addition would be appropriate only if it exposed a reusable renderer
primitive—such as generic dynamic-instance TLAS updates—not a Cloudflight
Ocean concept or artistic constant. No such addition is required here.

## Runtime behavior

The sample requires the native WebGPU backend. It retains a public WebGPU/TSL
rendering path whether or not the optional ThreeBrowser RTX capability surface
or Reflex support is present. The in-canvas help panel describes the live
flight controls and reports the active weather and runtime feature state.
